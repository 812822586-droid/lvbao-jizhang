# 绿宝记账 · 微信小程序（第一版）

> 一个人记账 + 一群人一起花钱时「谁该给谁多少钱」自动算清楚。
> 这是第一版（MVP）的**代码**。现在**不需要注册账号、不需要花钱**，就能在电脑上的「微信开发者工具」里打开看效果。

## 现在能做什么 / 还不能做什么

| 功能 | 现在（游客 AppID、本机体验模式） | 有了真 AppID + 云开发之后 |
| --- | --- | --- |
| 个人记账：记一笔、修改、删除、分类、按月汇总、分类占比条 | ✅ 能用，数据存在手机本地 | ✅ 同左，另可手动「备份到云端」 |
| 导入网页版绿宝记账的备份（先预览，重复导入不重复记账） | ✅ | ✅ |
| 导出表格（CSV） | ✅ | ✅ |
| 共同账本：新建、记账、平均分/指定金额分摊、最少转账算法、结清确认 | ✅ 能用，但只有你一个真人，朋友只能当「虚拟成员」，由你代记 | ✅ 朋友用自己的微信加入，各自在自己手机上记 |
| 邀请朋友（转发卡片到微信群） | ❌ 代码写好了，但需要云端才有意义 | ✅ |
| 隐私同意弹窗 + 隐私政策页 | ✅ | ✅（还要在后台填「用户隐私保护指引」） |
| 收钱 / 会员 / 广告 / AI / 理财类功能 | 🚫 第一版故意不做（见产品计划里的合规说明） | 🚫 |

## 第一步：安装微信开发者工具（Windows）

1. 用浏览器打开：<https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html>
2. 下载「稳定版 Stable Build」里的 **Windows 64** 版本，双击安装，一路点「下一步」。
3. 打开「微信开发者工具」，用你自己的微信**扫码登录**（只是登录开发者工具，不会注册任何东西，不花钱）。

## 第二步：打开这个项目

1. 把本文件夹 `lvbao-miniapp` 放在电脑上一个好找的地方（比如桌面）。
2. 在开发者工具首页点「**+**」（导入项目）。
3. 「目录」选择 `lvbao-miniapp` 这个文件夹（就是里面能看到 `project.config.json` 的那一层）。
4. 「AppID」这一栏会自动填好 `touristappid`（这是**游客模式**，不用注册）。
   如果它让你选，就选「测试号」或「使用游客模式」。**不要**随便填别的号。
5. 「后端服务」选「**不使用云服务**」。
6. 点「确定」。几秒钟后左边会出现手机模拟器，里面就是绿宝记账。

> 看不到界面？点工具顶部的「编译」按钮。出现红色报错就截图发给我。

## 第三步：照着这个清单点一遍（试玩）

1. **记账页**：点「＋ 记一笔」→ 填 `12.5` → 选「交通」→ 保存。首页出现这笔，上面的「支出」变成 12.50。
2. 点「‹ ›」切换月份；点一笔账可以修改或删除。
3. 底部点「**共同账本**」→「新建共同账本」→ 名字写「周末游」、昵称写「小张」→ 创建。
4. 在账本里「添加一位朋友的名字」，比如「小红」「小李」。
5. 点「＋ 记一笔」：写「住宿」、金额 `300`、谁先付钱选「小张」，参与的人全选，保存。再记一笔「餐费」`120`，付钱的选「小红」。
6. 点「看谁该给谁多少钱」：会写出「谁转给谁多少」，点名字可以展开看「为什么这么算」。
7. 点「我已转账」→ 再点「确认收到」，这一笔就变成「已结清」。
8. 点底部「我的」可以：导入网页版备份、导出表格、看隐私政策、清除全部数据。
9. 隐私弹窗：有真 AppID 并在后台填好隐私指引后，第一次打开会弹「用户隐私保护提示」。游客模式下开发者工具不一定会弹，这是正常的。

> ⚠️ 绿宝**不收钱、不代转账**。「我已转账」只是记一笔；真正的转账要你们自己在微信里转。

## 运行自动检查（可选，需要装 Node.js）

这些检查验证「分钱算对没有」。

1. 安装 Node.js（官网 <https://nodejs.org> 下载 LTS 版，一路下一步）。
2. 在 `lvbao-miniapp` 文件夹的地址栏输入 `cmd` 回车，打开黑色窗口。
3. 输入 `npm test` 回车。看到最后 `fail 0` 就是全部通过。

## 有了真正的 AppID 之后要做的事（只有你本人能做）

我没有替你注册、付款、提交任何东西。顺序见产品计划第 9、15 节：

1. 在 <https://mp.weixin.qq.com/> 注册小程序账号（管理员微信扫码实名）。主体选「个人」还是「企业/个体户」，**注册后不能改**。
2. 在后台提交备案、做微信认证（要刷脸、回短信、付认证费，都由你本人完成）。
3. 后台 → 开发管理 → 开发设置，复制你的 **AppID**。
4. 开发者工具：点右上角「详情」→「基本设置」→ 把 AppID 换成你自己的。
5. **开通云开发**（点工具栏的「云开发」按钮）→ 创建环境（先用免费的）→ 复制「环境 ID」。
6. 打开 `miniprogram/config.js`，把 `CLOUD_ENV: ''` 改成 `CLOUD_ENV: '你的环境ID'`，并把 `CONTACT` 改成你真实的联系邮箱。
7. 在开发者工具左边文件列表里，右键 `cloudfunctions/ledger` →「上传并部署：云端安装依赖」；`cloudfunctions/personal` 也一样。
8. 在「云开发 → 数据库」里新建 5 个集合：`ledgers`、`members`、`expenses`、`payments`、`personal_backups`。
   每个集合的权限都选「**所有用户不可读写**」（只有云函数能访问，这样别人才没法绕过检查直接读你的账）。
9. 在「云开发 → 数据库」给 `members` 集合的 `uid` 字段、`ledgers` 的 `ownerUid`+`clientId` 建索引（量大了会更快，量小可以先不建）。
10. 重新编译。用**两个不同的微信号**在真机上预览：一个创建账本并点「邀请朋友」，另一个点开卡片加入，验证两部手机同时记账。
11. 后台填「用户隐私保护指引」（内容见 `docs/隐私政策草稿.md`、`docs/审核说明草稿.md`），上传代码 → 设为体验版 → 提交审核。

如果你改了 `miniprogram/lib/` 里的文件，要运行 `npm run sync` 把它们复制给云函数（`npm test` 会检查两边是否一致）。

## 分钱规则（写在这里，方便你核对）

- 所有金额都用**整数的「分」**计算，不会出现 0.1+0.2=0.30000000000000004 这种误差。
- 平均分除不尽时：多出来的几分钱，按成员**加入账本的先后**从前往后每人多 1 分。
  例：100 元分给 3 人 = 33.34 / 33.33 / 33.33，合计仍是 100 元。
- 「指定金额」要求每个人的钱加起来**正好等于总额**，否则不让保存，并告诉你差多少。
- 谁没参加，就不要点他，他不分摊；付钱的人可以不参加分摊。
- 转账次数**尽量少**：需要转账的人不超过 16 个时，用精确算法保证次数最少；超过则用普通算法（仍然正确，只是不一定最少）。
- 只有「收款人点了确认收到」的转账才计入结清；「已标记转账」只是等待确认。结清后又改账，会提示重新对账。

## 已知限制（诚实说明）

- **界面我没能在真正的微信开发者工具里亲眼看过**。逻辑和每个页面的 JS 都用自动测试跑过，但样式、排版、真机兼容性需要你打开后看一眼并反馈。
- **云函数没有在真的云环境里跑过**，只用「假数据库」测了读写逻辑。第一次部署可能要调。
- 共同账本能不能通过个人主体的「工具—记账」类目审核，**提审前无法确认**（官方备注写着不含用户自定义内容记录及分享）。
- 个人账本云备份目前是「整份覆盖」：云上只保留最近一次，最多 3000 笔。
- 云数据库没有跨文档事务，两个人在完全同一瞬间加入/改同一笔账，极少数情况下可能要刷新重试（改同一笔账有版本检查，会提示冲突而不是悄悄覆盖）。
- 没做：退款/多币种/不等份数分摊、拍照和语音记账、订阅消息提醒、微信群身份绑定（`getGroupEnterInfo`）、会员收费、流量主广告。都在产品计划的第二、三版里。
