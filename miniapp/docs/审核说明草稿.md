# 提交审核时用的说明（草稿）

> 这是给你自己准备的材料，**我没有提交任何东西**。提交审核、选类目、填表都要你本人在 mp.weixin.qq.com 后台操作。

## 1. 建议选的服务类目

- 个人主体：「工具 → 记账」。
- 注意：微信官方类目表里，个人主体的「工具—记账」备注写着「不包含用户自定义生成内容记录及分享」。
  我们的「共同账本」有可能被判成超出这个范围，**能不能过审要提审后才知道**（产品计划里标为最大风险）。
- 如果被拒：不要换个名字再交，也不要绕开审核。按产品计划里的备选方案，改用符合条件的个体工商户/企业主体。

## 2. 备注里可以这样向审核人员说明共享功能（请按实际情况改）

> 本小程序是一个记账和 AA 分摊计算工具。「共同账本」只用于几个熟人（如聚餐、旅行的同伴）
> 一起记录共同花费并计算每人应出的钱。账本是私密的：不公开、没有广场/搜索/评论/点赞，
> 只有通过账本创建者发出的邀请并自己确认加入的成员才能看到。邀请卡片里只有账本名字，
> 没有金额。本小程序不收款、不代转账、不提供支付、理财或借贷功能；转账由用户自己在微信里完成，
> 小程序只记录“付款人说已转账、收款人确认收到”。基础记账不需要登录；加入共同账本不强制分享、
> 不要求提供手机号或头像。用户可以随时退出账本、删除自己的数据（我的 → 清除我的全部数据）。

## 3. 审核人员怎么体验（后台「审核备注」里写）

没有账号体系，不需要测试账号。体验路径：

1. 「记账」页点「记一笔」→ 填金额 → 保存。
2. 「共同账本」页 →「新建共同账本」→ 填名字和昵称。
3. 在账本里「添加」一位朋友（虚拟成员）→「记一笔」→ 选谁付钱、谁分摊 → 保存。
4. 点「看谁该给谁多少钱」查看结算。

## 4. 官方常见拒绝情形，对照检查（来自产品计划第 9 节）

| 检查项 | 现状 |
| --- | --- |
| 要求分享才能使用 | 不要求。基础功能不需要分享。 |
| 广告占功能页面超过 50% | 没有任何广告。 |
| 显示头像昵称要经用户同意 | 不读取微信头像；昵称是用户自己填的。 |
| 账号注销后要删除相关数据 | 「我的 → 清除我的全部数据」。云端模式会删云备份并匿名化共同账本里的身份。 |
| 有账号体系要给测试账号并提供退出登录 | 没有账号体系（微信身份自动识别）。 |
| 首页两次点击内到达所有服务页面 | 底部有「记账 / 共同账本 / 我的」三个标签页。 |
| 名称、简介不要用金融相关词 | 名称「绿宝记账」；简介请只写“记账、AA 分摊”，不要写理财、投资等词。 |

## 5. 「用户隐私保护指引」在后台怎么填

后台路径：设置 → 服务内容声明 → 用户隐私保护指引。内容必须和小程序实际行为一致，
可参考 `docs/隐私政策草稿.md`。当前版本涉及：

| 后台选项 | 要不要勾 | 说明 |
| --- | --- | --- |
| 微信昵称（手机端输入框 nickname） | 按实际勾「你选择的昵称」或类似项 | 昵称输入框用了 `type="nickname"`，用户自己填写。 |
| 剪切板 | 勾 | 「复制结算说明」「导出失败时复制表格」会写入剪切板。 |
| 选择的文件 | 勾 | 「导入网页版备份」用 `wx.chooseMessageFile` 读用户选的 json 文件。 |
| 位置、相册、相机、麦克风、通讯录、手机号 | 不勾 | 当前版本没有用到。以后加拍照识别要先更新指引。 |

> 具体选项名称以后台当时的页面为准。我没有登录后台，上表是根据代码里用到的接口整理的，请你对照后台逐项确认。
